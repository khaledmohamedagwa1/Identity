# P0 Foundations: task specs

P0 delivers the skeleton, building blocks, contracts and tooling that every later lane builds on. It ends at gate **G0 Contracts frozen** (week 2).

## F-01 Repo, solution skeleton, module template

**Lane** L0 · **Depends on** — · **Estimate** 2 d

**Goal:** a repository where a new bounded-context module can be created with one command and builds in CI.

**Scope**
- Folder layout from section 7.2; `global.json` pinning .NET 10 SDK; `Directory.Build.props` (nullable, warnings as errors, analyzers); `Directory.Packages.props` (central package management).
- `dotnet new platform-module -n <Name>` template that creates `Domain`, `Application`, `Infrastructure`, `Api`, `Contracts` projects with correct references.
- `.editorconfig`, `CODEOWNERS` per lane folder, PR template with the DoD checklist, `docs/adr` folder.

**Acceptance criteria**
- Template output compiles with zero warnings and passes architecture tests.
- `Domain` has no package references except building blocks.
- CODEOWNERS maps each folder to its lane.

## F-02 Domain and application building blocks

**Lane** L0 · **Depends on** F-01 · **Estimate** 4 d

**Goal:** shared DDD and CQRS primitives so modules write only business code.

**Scope**
- `Entity<TId>`, `AggregateRoot<TId>` (domain event list, version), `ValueObject`, `IDomainEvent`, `IIntegrationEvent`.
- Strongly typed IDs with UUIDv7 generation and EF/JSON converters (source generated or hand-written).
- `Result` / `Result<T>` with typed `Error` (code, message, type: Validation, NotFound, Conflict, Forbidden).
- Own dispatcher: `ICommand<T>`, `IQuery<T>`, handlers, pipeline behaviours: logging, validation (FluentValidation), tenant guard, unit of work, audit, idempotency key.
- Mapping of `Result` errors to RFC 9457 Problem Details in `Api` projects.

**Acceptance criteria**
- No dependency on MediatR, AutoMapper or other commercial packages.
- Pipeline order is fixed and documented; behaviours can be added per module.
- 95% line coverage on building blocks.

## F-03 Infrastructure building blocks

**Lane** L0 · **Depends on** F-02 · **Estimate** 4 d

**Goal:** persistence, tenant isolation and reliable event delivery available to every module.

**Scope**
- `ModuleDbContext` base: schema per module, strongly typed ID converters, `TenantId` global query filter for `ITenantOwned` entities, optimistic concurrency (`version`).
- `ITenantContext` + middleware that reads `tid` from the token; background jobs set it explicitly.
- RLS: `DbConnectionInterceptor` calling `set_config('app.tenant_id', @tid, true)` per transaction; migration helper to enable RLS and policies on tenant tables.
- Outbox: integration events saved in `platform.outbox` in the same transaction; inbox table for idempotent consumers.
- Domain events dispatched before commit (same transaction).

**Acceptance criteria**
- A query without tenant context on a tenant table returns zero rows (RLS), even with the EF filter removed.
- Outbox write and aggregate write commit or roll back together.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|

| TC-F03-02 | I | Same query with `IgnoreQueryFilters()` as Acme | Still only Acme rows (RLS) |

| TC-F03-04 | I | Same integration event delivered twice to a consumer | Processed once (inbox) |
| TC-F03-05 | I | Two concurrent updates of the same aggregate | Second fails with Conflict |
| TC-F03-06 | I | Connection reused from pool by another tenant's request | Tenant setting not leaked ( `set_config` local to transaction) |

## G-08 ADR: access token format

**Lane** L0 · **Depends on** F-04 · **Estimate** 1 d

**Goal:** decide JWT (RFC 9068 profile) vs reference tokens per client type.

**Scope:** recommended decision to evaluate: JWT for first-party clients and APIs (fast local validation, 10-minute life); reference tokens for third-party clients (instant revocation via introspection). Document claims (section 5.2), `typ: at+jwt`, size budget (< 1 KB), and how the SDK handles both.

**Acceptance criteria:** ADR merged before G0; AdminApi client model has a `tokenFormat` field.

## F-05 Permission catalog, OpenFGA model template and generator

**Lane** L5 · **Depends on** F-04 · **Estimate** 5 d

**Goal:** the authorization model is generated from the permission catalog and tested.

**Scope**
- Catalog format (YAML/JSON per application): key, description, implies, allowed conditions, resource types.
- Generator (C# console) that emits the model in section 5.3: per permission the `_here`, `_subtree`, `_below`, `_inherited` and final relation; implication relations; condition declarations.
- Model tests with the OpenFGA CLI test format, using `AcmeFixture` tuples.
- Benchmark script for 500 permissions.

**Acceptance criteria**
- Generated model passes `fga model validate`.
- Model tests cover C1, C2, C3, C6, C11, C15 (structure), C18, C23, C24.
- Generator is deterministic (same input → byte-identical output).
