# P2 Enterprise: task specs

These 13 tasks make the platform enterprise-ready: SSO, SCIM, custom domains, security policies, webhooks, delegation and machine access hardening. They end at gate **G2 Pilot** (week 14).

## E-01 Upstream OIDC identity providers and home-realm discovery

**Lane** L6 · **Depends on** P-02 · **Estimate** 5 d

**Goal:** tenant users sign in with their company's OIDC IdP (Entra ID, Google Workspace, Okta OIDC).

**Scope:** `IdentityProviderConnection` (OIDC: issuer, client ID, encrypted secret, scopes, claim mappings, enabled domains); dynamic authentication handler per connection (no app restart); HRD: email domain → verified domain → connection; `external_logins` linking by `iss + sub`; first login creates or links user per rules; test-connection endpoint.

**Acceptance criteria:** adding a connection takes effect without restart; `state`, `nonce` and PKCE used upstream; IdP errors shown with a friendly page and logged.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-E01-01 | I | Acme adds OIDC connection (mock IdP), user `x@acme.com` enters email | Redirected to mock IdP; returns with `amr` = `fed` |
| TC-E01-02 | I | Upstream returns token with wrong `nonce` | Login rejected |
| TC-E01-03 | I | Same IdP subject logs in twice | Same platform user (linked by iss+sub) |
| TC-E01-04 | I | Domain not verified | No HRD redirect; local login shown |
| TC-E01-05 | E | Real Entra ID test tenant | Login succeeds (manual/nightly) |

## E-02 SAML 2.0 service provider per tenant

**Lane** L6 · **Depends on** P-02 · **Estimate** 6 d

**Goal:** tenants connect SAML IdPs (AD FS, Okta, Ping, Entra SAML).

**Scope:** ITfoxtec.Identity.Saml2; per-connection SP metadata endpoint, ACS, SLO; metadata import (URL or XML) and manual config; signed AuthnRequests; assertion signature, audience, recipient, `NotOnOrAfter`, `InResponseTo` validation; replay cache; attribute mapping; certificate expiry monitor (warning 30 days ahead).

**Acceptance criteria:** unsigned or tampered assertions rejected; IdP-initiated login off by default (opt-in per connection).

## E-03 JIT provisioning with claim mapping

**Lane** L6 · **Depends on** E-01, E-02, A-03 · **Estimate** 4 d

**Goal:** federated users are placed into nodes and roles automatically (C26).

**Scope:** mapping rules per connection: claim/attribute → node (by code) and → role with mode; evaluation on every login; assignments created with `source = jit` and updated or removed when claims change; manual edits on JIT assignments flagged; dry-run tester in admin UI.

**Acceptance criteria:** mapped assignments converge to claims on each login; manual assignments never removed by JIT.

**Test cases**

| ID | Level | Scenario | Expected |

| TC-E03-03 | I | Admin manually adds Viewer at Dubai | Kept after next login |
| TC-E03-04 | I | Claim value has no mapping | User created with default role only; audit warning |

## E-04 SSO enforcement for verified domains

**Lane** L6 · **Depends on** T-02, E-01 · **Estimate** 3 d

**Goal:** users of an enforced domain can only sign in through their IdP (BR-10).

**Scope:** `enforced` flag per connection + domain; login blocks password and passkey for those emails; break-glass owner exempt; invitations to enforced domains accepted through the IdP; existing local credentials disabled (not deleted) when enforcement starts.

**Acceptance criteria:** no local sign-in path for enforced users; break-glass still works.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-E04-01 | I | `x@acme.com` tries password login after enforcement | Redirected to IdP |
| TC-E04-02 | I | Break-glass owner signs in with password | Allowed and audited |
| TC-E04-03 | I | Disable enforcement | Local credentials usable again |

## E-05 SCIM 2.0 server

**Lane** L6 · **Depends on** A-04 · **Estimate** 6 d

## E-07 Tenant security policies and step-up

**Lane** L3 · **Depends on** P-02, I-02 · **Estimate** 4 d

**Goal:** each tenant sets its own password, MFA and session rules (BR-11).

**Scope:** policy object: password rules, MFA required (all / admins only / off), allowed methods, session idle and absolute lifetime, remember-device days; enforced at login and tenant switch; step-up through `acr_values` (e.g. `urn:platform:acr:mfa`); `acr` claim in tokens.

**Acceptance criteria:** switching into a stricter tenant triggers step-up; policies audited.

**Test cases**

| ID | Level | Scenario | Expected |

| TC-E07-01 | E | Omar (no MFA) switches from Globex to Acme (MFA required) | Prompted to enrol/verify MFA first |
| TC-E07-02 | I | Client sends `acr_values=urn:platform:acr:mfa` | Token `acr` matches only after MFA |
| TC-E07-03 | I | Session idle 31 min with 30-min policy | Re-authentication required |

## E-08 Webhooks and event stream

**Lane** L7 · **Depends on** U-01 · **Estimate** 4 d

**Goal:** tenants receive events in their own systems.

**Scope:** subscriptions per tenant (URL, event types, secret); HMAC-SHA256 signature header with timestamp; retries with exponential backoff for 24 h; dead letters and manual redelivery; delivery log; SSRF protection (no private IPs).

**Acceptance criteria:** at-least-once delivery with idempotency key; receivers can verify signatures with sample code.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-E08-01 | I | Subscribe to `member.created` ; invite accepted | Signed POST received |
| TC-E08-02 | I | Receiver returns 500 three times | Retried; delivered on 4th; log shows attempts |
| TC-E08-03 | S | Subscription URL `http://10.0.0.5` | Rejected |

## E-10 Time-bound assignments and deputy delegation

**Lane** L4 · **Depends on** A-03, Z-02 · **Estimate** 4 d

**Goal:** temporary access and deputies while on leave (C18, C19, UC-12).

**Scope:** `validFrom`/`validUntil` on assignments (tuple condition `active_window`); `Delegation` aggregate from own assignment to another member, period required, no re-delegation, auto-revoked with source; cleanup job removing expired tuples; notifications before expiry.

**Acceptance criteria:** access starts and ends at the exact times (PDP uses server time); deputy cannot delegate further.

## E-11 Reconciliation, drift metric, read-your-writes

**Lane** L5 · **Depends on** Z-02 · **Estimate** 4 d

**Goal:** OpenFGA never silently drifts from PostgreSQL.

**Scope:** reconciler computing expected tuples per tenant from DB and diffing with OpenFGA `Read` (paged); repair mode; nightly schedule and on-demand per tenant; `authz_drift_tuples` metric and alert; `minRevision` support in PDP (wait ≤ 2 s on watermark, then higher consistency).

**Acceptance criteria:** injected drift (missing and extra tuples) detected and repaired; full reconcile of 1 million tuples < 15 min.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-E11-01 | I | Delete a tuple directly in OpenFGA | Reconciler reports 1 missing; repair restores it |
| TC-E11-02 | I | Write a stray tuple directly | Reported extra; repair deletes it |
| TC-E11-03 | I | Check with `minRevision` ahead of watermark | Waits then answers correctly |
| TC-E11-04 | P | 1 million tuples | Reconcile < 15 min |

## G-01 Token exchange policies and delegation

**Lane** L3 · **Depends on** P-03, G-03 · **Estimate** 5 d

**Goal:** API A can call API B on behalf of a user safely (scenario M3, section 9.3).

**Scope:** enable token-exchange grant; `TokenExchangePolicy` (client, source audience, target resource, allowed scopes, mode, max chain depth) managed via AdminApi; processing steps of section 9.3; nested `act` claim; no refresh token; audit `TokenExchanged`.

**Acceptance criteria:** deny by default; tenant never changes; scopes only narrow.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-G01-01 | I | Orders API exchanges Mona's token for Invoices API (policy exists) | New token `sub` =Mona, `act.sub` =orders client, `aud` =invoices |
| TC-G01-02 | I | No policy for that pair | `invalid_grant` |
| TC-G01-03 | I | Request scope not in subject token | Scope dropped or `invalid_scope` |
| TC-G01-04 | I | Chain depth 3 with max 2 | Rejected |
| TC-G01-05 | I | Subject token revoked | Rejected |
| TC-G01-06 | S | Public client attempts exchange | `unauthorized_client` |

## G-02 private_key_jwt client authentication and secret rotation

**Lane** L3 · **Depends on** P-01 · **Estimate** 3 d

**Goal:** confidential and machine clients authenticate without shared secrets.

**Scope:** client JWKS (inline or URL) per client; `client_assertion` validation (iss/sub = client_id, aud = token endpoint, exp ≤ 5 min, `jti` replay cache); client secret rotation with two active secrets and expiry; default auth method per client type.

**Acceptance criteria:** replayed assertion rejected; rotation causes zero downtime.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-G02-01 | I | Valid signed assertion | Token issued |
| TC-G02-02 | S | Same assertion `jti` reused | `invalid_client` |
| TC-G02-03 | I | Assertion with `aud` = another endpoint | Rejected |
| TC-G02-04 | I | Rotate secret; old and new used during overlap | Both accepted until old expires |
