# P4 Production readiness: task specs

These 7 tasks make the platform safe to run in production. They end at gate **G4 GA** (week 24).

## R-01 Kubernetes, high availability, backups, disaster recovery

**Lane** L10 · **Depends on** X-09 · **Estimate** 6 d

**Goal:** the platform survives node, zone and data failures.

**Scope:** Helm charts per host with health probes, resource limits, HPA, PodDisruptionBudgets, NetworkPolicies; PostgreSQL via CloudNativePG (3 instances, synchronous replica, WAL archiving to object storage, PITR); OpenFGA 3+ replicas on PostgreSQL backend; Valkey with replica; OpenBao HA; zero-downtime migrations (expand/contract); blue-green or rolling deploys; DR runbook and drill.

**Acceptance criteria:** RTO ≤ 1 h, RPO ≤ 5 min proven in a drill; rolling deploy with zero failed requests.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-R01-01 | Drill | Delete primary PostgreSQL pod under load | Failover < 60 s; no committed data lost |
| TC-R01-02 | Drill | Restore whole cluster to a point 10 min ago in a new namespace | Done < 1 h; data matches |
| TC-R01-03 | P | Rolling deploy of all hosts during k6 load | 0 failed requests |
| TC-R01-04 | S | Pod in Workers namespace calls OpenBao admin API | Blocked by NetworkPolicy |

## R-02 Security review and penetration test

**Lane** L10 · **Depends on** G3 · **Estimate** 8 d (incl. fixes)

**Goal:** no known high or critical vulnerability at GA.

**Scope:** STRIDE threat model review per context; OWASP ASVS L2 checklist; DAST with OWASP ZAP on login, portals and APIs; dependency and container scanning (Trivy, OSV); external pen test focused on tenant isolation, OAuth flows, SAML, SCIM and PDP bypass; fix and retest.

**Acceptance criteria:** zero open high/critical; medium findings have dated plans; report archived.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-R02-01 | S | Cross-tenant IDOR attempts on every AdminApi route (Acme token, Globex IDs) | All 403/404 |
| TC-R02-02 | S | OAuth attacks: open redirect, code injection, PKCE downgrade, mix-up | All blocked |
| TC-R02-03 | S | SAML XML signature wrapping | Rejected |
| TC-R02-04 | S | ZAP full scan on login and portals | No high findings |

## R-03 SLOs, alerts, runbooks, on-call

**Lane** L10 · **Depends on** R-01 · **Estimate** 4 d

**Goal:** problems are detected and handled before customers notice.

**Scope:** SLOs (login availability 99.95%, token p95, PDP p95, propagation p99) with error-budget burn alerts; alerts for outbox lag, drift, cert expiry, key rotation failures, DB replication lag; runbooks for each alert; on-call rota; status page; game day.

**Acceptance criteria:** every alert links a runbook; game day resolves 3 injected incidents within targets.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-R03-01 | Drill | Stop sync worker for 5 min | Outbox-lag alert fires < 2 min; runbook restores |
| TC-R03-02 | Drill | Signing key rotation job fails | Alert; manual rotation per runbook works |
| TC-R03-03 | Drill | PDP latency injected (+100 ms) | SLO burn alert fires |

## R-04 OpenID conformance

**Lane** L3 + L11 · **Depends on** X-06 · **Estimate** 4 d

**Goal:** independent proof that the protocol implementation follows the standards.

**Scope:** run the OpenID Foundation conformance suite (self-hosted, open source) for OP profiles we support: Basic, Config, Dynamic (if G-06 shipped), Form Post, RP-initiated and back-channel logout, and FAPI 2.0 security profile if PAR + DPoP are offered; fix failures; optional certification.

**Acceptance criteria:** all selected test plans pass with no failures (warnings documented).

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-R04-01 | C | OIDC Basic OP test plan | All pass |
| TC-R04-02 | C | Config OP test plan | All pass |
| TC-R04-03 | C | Back-channel logout test plan | All pass |

## R-05 Tamper-evident audit and retention

**Lane** L7 · **Depends on** U-01 · **Estimate** 3 d

**Goal:** audit logs can prove they were not altered.

**Scope:** hash chain per tenant per day (each entry stores hash of previous + own content); daily anchor hash stored separately (object storage with retention lock); verification job and API; retention policies per tenant with legal hold.

**Acceptance criteria:** any modified or deleted entry is detected by verification.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-R05-01 | I | Modify one audit row directly in DB | Verification reports break at that entry |
| TC-R05-02 | I | Delete a row | Chain break detected |
| TC-R05-03 | I | Legal hold on Acme, retention passes | Rows kept |

## R-06 Documentation and developer portal

**Lane** L0 · **Depends on** G3 · **Estimate** 5 d

**Goal:** customers and developers succeed without support.

**Scope:** developer portal (static site): quick starts for ASP.NET Core, Angular, Node; SDK reference; OAuth flow guides including token exchange and M2M (section 9); permission catalog guide; API reference from OpenAPI; admin guide; IT-admin guides per IdP (Entra, Okta, Google, AD FS); migration guide (G-15); Arabic versions of admin guides.

**Acceptance criteria:** a developer new to the platform protects a sample API in < 30 min following the quick start; pilot customer review done.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-R06-01 | Review | New developer follows ASP.NET quick start | Protected API in < 30 min |
| TC-R06-02 | Review | Link checker on portal | 0 broken links |
| TC-R06-03 | Review | Code samples compile in CI | All pass |

## R-07 Pilot migration and go-live

**Lane** All · **Depends on** R-01 to R-06 · **Estimate** 5 d

**Goal:** first production tenant live with a rollback plan.

**Scope:** go-live checklist (security, SLOs, backups, on-call, docs, legal); pilot tenant migration using G-15 and O-04 with dry runs; DNS and custom domain cutover; hypercare for 2 weeks; GA announcement and post-launch review.

**Acceptance criteria:** all checklist items signed; pilot users sign in with old passwords; no Sev-1 in the first week.

**Test cases**

| ID | Level | Scenario | Expected |
|---|---|---|---|
| TC-R07-01 | E | Dry-run migration of pilot data to staging | 100% users and nodes imported; sample logins pass |
| TC-R07-02 | E | Production cutover rehearsal with rollback | Rollback < 30 min |
| TC-R07-03 | E | Smoke suite on production after cutover | All green |
