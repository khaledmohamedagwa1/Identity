# Identity platform web (Angular workspace)

Lanes L8 (admin portal + shared) and L9 (account portal). Spec: section 7.8, task F-10.

| Project          | Path                                                    | Prefix                     |
| ---------------- | ------------------------------------------------------- | -------------------------- |
| Admin portal     | `projects/admin-portal`                                 | `adm-`                     |
| Account portal   | `projects/account-portal`                               | `acc-`                     |
| Shared libraries | `projects/shared/src/{auth,permissions,ui,api-clients}` | `ip-` (`appCan` directive) |

Shared code is imported through path aliases: `@ip/shared/auth`, `@ip/shared/permissions`, `@ip/shared/ui`, `@ip/shared/api-clients`.

## Commands

```bash
npm ci
npm start                  # admin portal on :4200 (proxies /bff, /api, /pdp to Bff.Host)
npm run start:account      # account portal on :4300
npm run api:generate       # regenerate typed clients from OpenAPI (runs automatically before start/build/test/lint)
npm run lint
npm test                   # Vitest unit tests for shared + both apps
npm run test:api-regeneration   # TC-F10-02
npm run build
npm run e2e                # Playwright smoke, LTR + RTL (TC-F10-01); backends mocked with page.route
npm run licenses:check     # npm license allow-list
```

## How things fit

- **Auth (BFF pattern).** The browser only holds Bff.Host's HttpOnly cookie. `BffAuthService` reads `GET /bff/user`, and
  sign-in, sign-out and tenant switching are full-page redirects to `/bff/login`, `/bff/logout`, `/bff/switch-tenant`.
  State-changing requests carry `X-CSRF: 1` (`csrfInterceptor`). No token is ever stored in the browser.
- **Tenant context.** Admin routes live under `/t/:tenantSlug`. `tenantGuard` checks the slug against the session's
  tenant and asks the BFF to re-authorize when it differs. APIs still take the tenant only from the token.
- **Permission-aware UI.** `PermissionService` loads `GET {pdp}/v1/me/permissions?scope=<nodeId>` per node, caches it,
  and fails closed. Use `*appCan="'users_manage'; on: nodeId"` in templates and `requirePermission('users_manage')` on
  routes. This only hides UI: the server always enforces.
- **API clients.** Generated by `ng-openapi-gen` into `projects/shared/src/api-clients/generated` (git-ignored) from
  `../docs/api/admin-api.v1.yaml` and `../docs/api/pdp.v1.yaml`. Until those contracts are published (F-06), the
  generator falls back to the minimal stubs in `openapi/`. Never hand-write request or response types.
- **i18n.** English and Arabic at runtime (`TranslationService`, `| t` pipe). The active locale sets `<html lang dir>`
  and the CDK direction, so Material mirrors for RTL. Choose with the toolbar button or `?lang=ar`.
- **Theme.** Design tokens in `projects/shared/src/ui/styles/_tokens.scss` drive the Material 3 theme (`_theme.scss`);
  components use CSS custom properties only. No web fonts are downloaded (strict CSP).

## Adding a feature area (W-02 .. W-06)

1. Create the feature under `projects/<app>/src/app/<feature>/` with standalone components and an NgRx SignalStore.
2. Add a lazy route under the shell with `canActivate: [requirePermission('<key>')]`.
3. Add a `NavItem` with the same `permission` so the link is hidden when not granted.
4. Add English and Arabic texts to the app catalog in `src/app/i18n/`.
5. Add a Playwright spec under `e2e/<app>/` named after the spec's test case IDs.
